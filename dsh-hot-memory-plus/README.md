# dsh-hot-memory-plus —— 「热记忆」的增补件

**不改 dsh-hot-memory 一行代码**：只读它的产物（DSH_HOME/hot-memory/<sessionId>.md），补它还没有的两种能力。

## 为什么不改本体

写这个插件的时候，hot-memory 的 index.js **是几分钟前刚被另一个会话改过的**
（它正在加「中枢投喂」，字段注释里直接写着 R22），旁边还躺着 index.js.bak_R22_20260920_1045。
两条会话改同一个文件 = 互相覆盖，而且查不出是谁覆盖的。

所以换了合作方式：**读它的产物，不动它的代码**。这也顺带让升级互不干扰 ——
它改它的蒸馏逻辑，这里只消费结果。

## 补的两条（都是从 meow-memory 蒸馏来的）

调研见 <工作区>\_research\meow-memory-调研与可借鉴点.md。

### ① 压缩后召回

会话被压缩（/compact 或 token 压力自动触发）后会「突然失忆」。
监听 compaction/start 与 compaction/end 事件 → 在压缩后的**下一个步骤**，把

- 本会话热记忆全文（≤2KB 的短备忘，原文）
- 工作区教训最近 12 条

注入一次。为什么这里敢注入全文：**只在压缩后注入一次**（约 500-800 token），
而不是每轮都注入 —— 一次性成本换回被甩掉的记性。这是 meow-memory 那条做法里
唯一和我们「一行指针」哲学不冲突的部分。

实现细节：不在压缩事件里抢时序去 agent.inject，而是打个标记，
在 **agent/pre-step** 把这批消息追加进 enter 批次 —— 这样既不打断压缩，
也不会和这一轮已领取的输入抢位置。

**而且它带一个可核实的量**（这条是 指挥台 提的）：召回之后回头量一次 ——
**这次召回带过去的关键项，有多少在下一次蒸馏出的热记忆里仍然在**（按字符二元组重合率判断，容忍改写）。

    ratio 高  ⇒ 「模型把它读进去、蒸馏时保留了下来」的**弱证据**
    ratio 低  ⇒ 如实报告「没留下痕迹」，绝不夸大成「记住了」

前提是**产物 mtime 必须比召回时刻新**（否则拿旧备忘比对，当然"全都在"，那是假绿 ——
这条正好就是 指挥台 自己写进教训层的那条纪律）。热记忆在这些轮里一直没更新，就记一条
recall-audit-unmeasurable，不编数字。

### ② 跨会话教训层

一个工作区级共享文件：DSH_HOME/hot-memory/_shared/lessons.md（只追加）。

- 工具 **lesson_write**：写一条教训（自动去重：同一条重复写不会重复入库；作者取门铃别名，没有就用短 id）
- 工具 **lesson_read**：读最近 N 条
- **只在教训更新过时**注入一行指针（约 40 token，每会话一次）—— 有新东西才打扰

「已见」状态落盘（seen.json），所以**插件重载 / DSH 重启都不会把同一批教训重复提示**。

## 实机证据（2026-09-20 装好后当场记下的）

    探针 GET /hot-memory-plus → counters { compactions: 1, recalls: 1 }
    事件日志里三条 pointer，分别发给三个不同会话：
      56a1feec（指挥台）· 8162c2dd（修饰系统）· 1e334d94
    → 一个会话写下教训，另外两个会话各自收到了一行提示（跨会话那一条真的通了）
    同时有一个真实会话发生了压缩，召回也发出去了

这与我自己的体感一致：写第一条教训之后，我这一轮就收到了那行指针。

## 入口

    探针：GET http://127.0.0.1:3080/hot-memory-plus
          返回：教训路径与条数、待召回会话、计数器、最近 8 条事件
    工具：lesson_write / lesson_read（任何会话可调）
    状态：DSH_HOME/dsh-hot-memory-plus/state.json（启动时写，含 at 时间戳）
    事件：DSH_HOME/dsh-hot-memory-plus/events.jsonl（compaction / recall / pointer 各一行）

## 装 / 卸 / 改

    node install.mjs            # junction + patch 行 + profile 的 link 依赖
    node install.mjs --remove   # 三样一起撤
    node verify.mjs             # 24 项断言，假 ctx + 假 agent + 临时 DSH_HOME

## 已知限制（诚实边界）

- **召回只在压缩后触发一次**；模型有没有真的「用上」召回的内容，取决于模型 ——
  本插件只能保证「材料送到它面前了」，保证不了它读。
  **但这一点现在有量了**：recallAudit 的 ratio（见上）。它是弱证据，不是强证据，别过度解读。
- **教训层靠会话主动写**，不自动提炼。自动提炼需要额外模型调用，那是 hot-memory 的蒸馏在做的活。
  这里刻意只做「有了通道」这件事，避免和它重复花钱。
- **指针是「每会话每次变更一次」**，不是每轮 —— 想让它更显眼就得付出每轮 token 的代价，不划算。
- **它是增补件**：如果 hot-memory 本体以后自己加了压缩召回或教训层，这个插件就该退休
  （卸载一条命令，不影响热记忆本体）。
- 注入的消息来源标成 plugin + form: recall，UI 会把它当「另一处提取来的材料」呈现。
